# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is
`autoshorts`: video/channel link -> best moments -> 9:16 clips saved to `ready/<date>/` with a `.txt` (title, description) and `.jpg`. Nothing is posted unattended: YouTube upload happens only from a per-clip button with a confirmation (`publish.py`); Instagram/TikTok are manual (a Postiz auto-poster was built and dropped at the user's request; TikTok's API only allows private posts for unaudited personal tools). Python >=3.10 (FastAPI + uvicorn; Pillow for text layers via `.[editor]`); external tools: `ffmpeg`, `ffprobe`, `yt-dlp`. User-facing strings are mostly Turkish. The earlier createclip app (web editor, face layout) lives only in git history (last commit before the rewrite: `88e08c3`); `sources/` was ported from it.

## Commands
```bash
./.venv/bin/pip install -e ".[dev,editor,faces]"   # faces = OpenCV; clipsai extra is experimental and left out
./.venv/bin/python -m pytest -q                    # tests/ (no network)
./.venv/bin/python -m pytest tests/test_all.py::test_export_saves_video_and_text -q
./.venv/bin/autoshorts doctor
./.venv/bin/autoshorts serve --open      # web UI at http://127.0.0.1:8765 (needs . and `cd web && npm run build`)
./.venv/bin/autoshorts --root /tmp/x run "<url>" --at 0:20:00-0:20:40   # real e2e without chat analysis
cd web && npm install
npm run dev                              # 5173, proxies /api and /media to 8765 (keep `autoshorts serve` running)
npm run build                            # tsc, then vitest, then vite build: a failing test blocks the build
npm test                                 # vitest only; one file: npx vitest run src/lib/time.test.ts
```
No linter or formatter is configured.

`--root` selects the working folder holding optional `autoshorts.json` and `data/` (SQLite db, caches, clips) plus the output folder (`ready/`); default is the current directory. Gitignored.

## Architecture (`autoshorts/`)
- `download.py` stage 1 (yt-dlp): `info`, `fetch_range` (stream-copy of a time range, retries, `has_video` check), `fetch_audio`, `list_videos`. Kick live broadcasts work like VODs: `kick.vod_info` sets `Vod.live`/`Video.live` and `duration` = elapsed - `LIVE_MARGIN` (40 s); manual moments go through `pipeline.clamp_live`. **429 / bot-check output raises `BlockedError`**, which pipeline code must propagate (stop, leave video `pending`) instead of retrying.
- `finder.py` stage 2: engines chat / audio / transcript (ClipsAI, optional, untested here) / auto. Chat and peak maths live in `sources/` (`kick.py` resumable chat crawler with rate limiter, `youtube.py` chat replay, `peaks.py` z-score peaks incl. `skip_start`); ported from the earlier app apart from imports, so keep their measured constants (Kick ~1.5 req/s).
- `render.py` stage 3: exact trim + 9:16 on black bars (no blur) + loudnorm. `meta.py` rule-based title/description. `export.py` copies the result into the output folder.
- `api.py` (FastAPI, `serve` default) serves `web/dist` + JSON API + SSE job events (`/api/jobs/<id>/events`, replayable via `after`/Last-Event-ID) + range media; `jobs.py` is the single-worker job runner with cancel and a per-job event log. `pipeline.process_video` / `finder.find` emit structured events (`info`, `chat`, `activity` (partial then final), `moments`, `clip`, `done`, `end`) next to the `progress(frac, text)` callback; the React home page draws them. Keep event payloads backward compatible with `web/src/lib/useJob.ts`. The docked terminal on the home page (`web/src/components/Terminal.tsx`) renders `log` events (`level`: info/step/cmd/ok/warn/err): `jobs.py` emits them from `say`, from `progress` ticks (at once on a step change, else every 8 s) and, via `proc.set_log_hook`, for every external command `proc.run` starts and finishes. The hook is set per job and cleared in `finally`.
- `web/` React 19 + Vite + TypeScript + Tailwind v4 + motion. Design tokens live in `web/src/index.css` (paper/ink/lime, Inter Variable). Pages: `Home` (paste link -> live timeline scenes), `Panel` (overview, clips, channels, settings).
- `editor.py` + `web/src/pages/Editor.tsx`: clip editor. A clip keeps its padded source footage (`data/clips/source/<id>.mp4`, `src_start/src_end` columns; `source_pad` seconds each side). The edit is one JSON `project` (trim in source-file seconds, layout mode `blur|crop|stack` (`blur` is kept as the mode name but renders black bars) with window cells `{cx,cy,zoom}`, audio) stored in table `edits`. **Preview and export share geometry**: `editor.cell_rect/build_graph` (ffmpeg) mirror `web/src/lib/layout.ts` (`cellRect/plan`, CSS); change both together and keep `test_layout_geometry_matches_between_modes` green. Export is a `jobs` kind (`export`), progress via ffmpeg `-progress`; `source` jobs fetch footage for clips that predate the editor. Timeline assets (`strip.jpg` sprite, `wave.json`) are cached in `data/clips/editor/<id>/`.
- **Text layers** (`texts.py`, `web/src/lib/texts.ts`, `TextLayer`, `TextPanel`): `project.texts[]`, times in seconds from the CLIP's start (not source seconds, unlike the trim). Pillow renders one PNG per layer; `render_project` chains `overlay=...:enable='between(t,a,b)'` after the layout graph, ending in `[v]`. Wrapping, block geometry, baselines and the emoji advance are mirrored in `texts.ts`; change both together. Emoji use Apple Color Emoji through Pillow (no raqm, so no ZWJ sequences). Fonts: `fonts.py` / `web/src/lib/fonts.ts`. Word-by-word captions existed and were removed on purpose (old projects' `captions` key is dropped by `clean_project`).
- **Source timestamps:** stream-copied sections keep the original stream's timestamps (e.g. start 1.17 s); browsers play from that offset while `ffmpeg -ss` counts from the first frame, so `editor.source_info` remuxes such files to start at 0 (`normalize_source`). Never skip this when adding another way to obtain a source file.
- **Face layout** (`faces.py`, `editor.face_layout/stack_heights`, `FacePanel` in `Editor.tsx`): `project.layout.split` (0.25-0.75) is the top window's share of the 1920 px height, in even pixels (`stack_heights` mirrors `stackHeights` in `layout.ts`; `web/src/lib/layout.test.ts` pins the numbers, run by `npm run build`). Face detection is OpenCV Haar over ~14 sampled frames, keeping the position seen most often; cached in `data/clips/editor/<id>/face.json`. Config `layout: face` makes `make_clip` render through `editor.render_project` and save the project; no face found = the black-bar layout.
- `jobs.py` also runs a watchdog thread: no progress for `stall_min` minutes stops the job (status `failed`, "Takıldı"), 5 minutes warns in the terminal. After `run`/`scan` jobs `editor.clean_old_sources` deletes source footage older than `keep_source_days` for clips without a saved edit. Kick request stats reach the terminal via `proc.say` from `sources/kick.py`.
- **Giveaway spam** (`sources/peaks.py`: `analyze/weight/spam_report`): chat votes weigh 0 for `!commands` and for texts longer than `SHORT` chars that dominate >=`CAMPAIGN_BINS` ten-second bins within `CAMPAIGN_SPAN` s (campaign), `LOCAL_WEIGHT` inside a single dominated bin; short shouts and laughter (`LAUGH`) are exempt and random different text is never filtered (hype moments must stay moments); `peaks_from_scores` and caps `cap_n=3` peaks per `cap_window=600` s. Manual (`--at` / Tekli klip page `web/src/pages/Single.tsx`, `lib/time.ts`) moments are never snapped to sentences.
- **Power profile** (`power.py`, config `power` eco|normal, applied per job/CLI run via `power.apply`): eco = `h264_videotoolbox -q:v 65` when available (else x264), `-threads/-filter_threads 2`, and `proc.run` prefixes every child with `nice -n 10`; normal = x264 veryfast crf 21, all cores. Every ffmpeg encode goes through `power.video_args/input_args/filter_args`. `taskpolicy -b` was measured 2.3x slower (E cores only), so it is not used.
- **YouTube upload** (`publish.py`, stdlib only): OAuth loopback + PKCE (`/api/youtube/callback`), credentials in `data/youtube/`; `upload` is a `jobs` kind with resumable chunks; `next_slot` fills the `upload_times` slots (local time) when the job runs; `clips.yt_id/yt_publish_at` block a second upload. Scheduled = private + `publishAt`.
- **Weekly montage** (`top5.py`, `web/src/components/Top5.tsx`): job kind `top5` joins 2-5 finished clips (request items in rank order, played last place first) in one ffmpeg `concat` pass, overlays drawn with `texts.py`, max 180 s. The result is a normal clip row with `engine="top5"` and a made-up `video_url` (`top5:<ns>`): it has no source footage, so editor/source actions must stay hidden or refused for it.
- **Analytics** (`analytics.py`, `web/src/components/Analytics.tsx`): one live YouTube Analytics "top videos" report (`dimensions=video`, max 200, no `video==` filter documented) joined with clips that have `yt_id`, including deleted ones (`yt_streamer` is stored at upload for that). Needs the `yt-analytics.readonly` scope (`publish.status()["analytics"]`) and the Analytics API enabled in the Cloud project.
- **API guard** (`api.py` middleware): the `Host` header must be local, and every `POST`/`PUT` must send a JSON content type (blocks cross-site form posts), even without a meaningful body.
- **Settings:** a new key goes in `config.DEFAULTS`; to be changeable from the web UI it also needs a validator in `api.EDITABLE`.
- **Re-runs** (`store.py`, `pipeline.process_video`): links of one broadcast (`fingerprint`/`twins`) share a clip pool; candidates within `NEAR` (15 s) of an existing clip are skipped and the finder is asked for extra moments so the requested count is still new ones; a video first processed while live resumes after its last clip (`resume_point`). A Kick channel link resolves to the running broadcast (`download.resolve`).
- `autoshorts build-ui` bundles `web/dist` into `autoshorts/webdist` (gitignored; `config.ui_dist()` prefers it).
- `store.py` SQLite (sources, videos, clips; clip status `new -> done | failed`); `pipeline.py` ties it together (`process_video`, `make_clip`, `scan_sources`, `watch_once`); `cli.py` is argparse only.
- `proc.run` runs every subprocess in its own process group and kills the group on timeout (a stalled yt-dlp child ffmpeg otherwise hangs the caller).
